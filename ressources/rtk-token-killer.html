RTK : le proxy qui coupe jusqu'à 90% de tes tokens

Claude Code / Cursor / Codex · Gagner du temps · Niveau intermédiaire

Tu as commenté RTK : voilà l'outil et son installation exacte. RTK, pour Rust Token Killer, est un proxy en ligne de commande qui filtre la sortie de tes commandes (git, grep, find, tests, logs) avant qu'elle n'arrive à ton assistant IA. Résultat : jusqu'à 90% de tokens en moins envoyés à Claude Code, Cursor ou Codex.

Le problème qu'il règle

Quand ton agent lance un git status, un grep ou une suite de tests, la sortie brute part en entier dans le contexte. Sur un gros repo, c'est des milliers de tokens de bruit — répétés à chaque tour de conversation. Tu paies pour ça, et ta session sature plus vite.

RTK s'intercale entre la commande et l'agent : il garde le signal utile, jette le reste. Concrètement :

  • Tu paies beaucoup moins de tokens sur chaque commande
  • Tes sessions durent plus longtemps avant de saturer le contexte
  • Zéro changement dans ta façon de travailler : le hook réécrit les commandes tout seul

Étape 1 — Installer le binaire

Une seule commande installe RTK (version ~0.44 au moment où on écrit) :

curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/master/install.sh | sh

Étape 2 — Ajouter RTK au PATH

Le binaire s'installe dans ~/.local/bin. Ajoute-le à ton PATH en collant cette ligne dans ton ~/.bashrc (ou ~/.zshrc) :

export PATH="$PATH:$HOME/.local/bin"

Recharge ton terminal (ou source ~/.bashrc) pour que le changement prenne effet.

Étape 3 — Vérifier l'installation

rtk --version rtk gain

rtk --version doit afficher rtk X.Y.Z. rtk gain te montre les économies de tokens déjà réalisées — c'est aussi le test qui confirme que c'est bien le bon binaire (voir le piège plus bas).

Étape 4 — Activer RTK dans Claude Code

Cette commande branche le hook PreToolUse sur le Bash de Claude Code, directement dans ton ~/.claude/settings.json :

rtk init -g --auto-patch

À partir de là, chaque commande bash que Claude lance (par ex. git status) est automatiquement réécrite en rtk git status — de façon transparente, sans surcoût de tokens. Puis redémarre Claude Code.

Étape 5 — Confirmer que tout est au vert

rtk init --show

Cette commande affiche l'état de la configuration : le hook doit apparaître comme actif.

⚠ Deux pièges à connaître

1. Le hook ne s'active qu'APRÈS un redémarrage. Tant que tu n'as pas relancé Claude Code, le hook PreToolUse n'est pas chargé et RTK ne filtre rien — tu croiras que ça ne marche pas. Redémarre, c'est tout.

2. Collision de nom possible. Un autre outil s'appelle aussi rtk (Rust Type Kit). Si rtk gain te sort « command not found » ou une erreur bizarre, tu as probablement le mauvais binaire. Vérifie avec which rtk et rtk gain : le vrai RTK répond aux commandes gain, discover et proxy.

Ce à quoi t'attendre

  • Des sorties de commandes bien plus courtes dans ton agent, dès le premier git ou grep
  • rtk gain qui chiffre les tokens économisés au fil des sessions
  • Une facture d'API qui baisse et des sessions qui tiennent plus longtemps
