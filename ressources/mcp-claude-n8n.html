n8n + MCP : connecter Claude à tes workflows, sans une ligne de code

n8n + protocole MCP · Agent IA connecté · Niveau débutant / intermédiaire

n8n a intégré nativement le protocole MCP (Model Context Protocol) — et presque personne ne s'en sert encore. Concrètement : avant, brancher Claude à tes outils demandait des heures de code API, un serveur, de l'authentification. Aujourd'hui, un seul nœud dans n8n expose tes workflows comme des outils que Claude peut appeler tout seul.

Tu poses une question à Claude, il va chercher la donnée dans n8n, il agit, il revient avec le résultat. Zéro ligne de code côté agent.

Le workflow n8n, prêt à importer

Un MCP Server Trigger + deux outils d'exemple (lecture d'un Google Sheet, déclenchement d'un workflow par webhook). Importé et validé sur une instance n8n réelle avant d'être publié ici.

◈ Télécharger le workflow n8n (.json)

Ce qu'il te faut

  • n8n récent (le nœud « MCP Server Trigger » est natif depuis les versions 1.88+) — auto-hébergé ou cloud
  • Un compte Claude qui accepte les connecteurs MCP distants (Claude.ai avec connecteurs personnalisés, ou Claude Code)
  • Pour l'outil d'exemple : une credential Google Sheets connectée dans n8n

Comment ça marche, en cinq étapes

1

Le nœud MCP Server Trigger expose une URL. C'est ton serveur MCP — n8n s'occupe de tout le protocole.

2

Chaque nœud « Tool » branché dessus devient un outil visible par Claude, avec son nom et sa description.

3

Tu colles l'URL du trigger dans la config MCP de Claude (Settings → Connectors → Add custom connector).

4

Claude découvre les outils tout seul : « Lire les leads », « Déclencher un workflow »…

5

Tu discutes. Claude choisit l'outil, l'appelle avec les bons paramètres, et te répond avec le résultat réel.

Les deux outils fournis dans le template

Lire les leads — un nœud Google Sheets en lecture. Remplace le Sheet d'exemple par n'importe quelle source : tes commandes, ton CRM, ton suivi de projets. Claude pourra répondre à « combien de leads cette semaine ? » avec tes vrais chiffres.

Déclencher un workflow — un nœud HTTP Request qui appelle le webhook de ton choix. C'est le pont vers tout le reste de ton n8n : Claude peut lancer une relance, une génération de rapport, une publication — n'importe quel workflow qui a un webhook.

💡 Le vrai déclic

Un outil MCP n'est pas limité à « lire une donnée ». Chaque workflow n8n que tu possèdes déjà peut devenir un outil de Claude en dix secondes : ajoute un nœud Tool qui pointe vers son webhook, donne-lui une description claire, c'est tout. Trois workflows connectés = un agent qui pilote ton business en langage naturel.

Installation, pas à pas

1. n8n → Workflows → Import from File → mcp-claude-n8n.json 2. Ouvre « Lire les leads » → branche ta credential Google Sheets → choisis ton document et ton onglet 3. Ouvre « Déclencher un workflow » → mets l'URL d'un webhook à toi 4. Active le workflow (toggle en haut à droite) 5. Ouvre le nœud MCP Server Trigger → copie la Production URL 6. Claude → Settings → Connectors → Add custom connector → colle l'URL
⚠ Le piège classique

L'URL MCP n'existe qu'en mode actif. Si tu testes avec le workflow désactivé, Claude verra un serveur vide ou une erreur de connexion — et rien ne te dira pourquoi. Active d'abord, connecte ensuite.

⚠ Sécurité : ne laisse pas le serveur ouvert

Par défaut le trigger est exposé sans authentification — pratique pour tester, dangereux pour durer. Dès que ça marche, ajoute une authentification Bearer dans le nœud MCP Server Trigger (champ Authentication) et renseigne le même token côté Claude. Tes workflows pilotent tes vraies données : traite cette URL comme un mot de passe.

Ce à quoi t'attendre

  • Claude répond avec tes données réelles, pas des généralités
  • Chaque nouveau workflow n8n devient un super-pouvoir de plus pour ton agent
  • Aucun serveur à coder, aucun SDK à apprendre : n8n parle MCP nativement
  • Ça marche depuis Claude.ai, Claude Code, et tout client MCP standard
